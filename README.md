# 个人下载器

独立于工作区内其他项目的 Windows 桌面下载器。普通 HTTP/HTTPS 直链使用内置 Range 分段下载器；视频页面（YouTube、Bilibili 及 yt-dlp 支持的其他数百个站点）由 yt-dlp 提取格式并下载，FFmpeg 负责合并独立音视频流。

## 启动

1. 安装 Python 3.10 或更新版本（Windows 安装时启用 Tcl/Tk）。
2. 双击一次 `安装媒体支持.bat`，在应用目录创建 `.venv` 并安装 yt-dlp 与 imageio-ffmpeg（携带 FFmpeg）。
3. 双击 `启动下载器.vbs`（静默启动，无 CMD 窗口；旧版 `启动下载器.bat` 已移除）。
4. 普通文件可粘贴直链；扩展默认开启“自动接管我点击的文件下载”，响应最近 8 秒内真实点击链接或按钮后创建的文件下载（包括 fwlink 等跳转链接、按钮触发的下载），并支持下载链接重定向（任务使用重定向后的最终地址命名）。页面自行发起、没有任何点击的下载不会转交。若 Chrome 弹出“另存为”，需在 Chrome 设置 → 下载中关闭“下载前询问保存位置”，然后重新点击链接。YouTube / Bilibili 视频页点“发送当前视频页到下载器”创建站点下载任务。
5. 下载列表支持 Ctrl/Shift 多选任务后批量移除；确认框可选择是否同时删除已下载文件和临时分段文件。下载地址输入框右键可粘贴、复制、剪切或全选。在下载列表的行上右键，可打开该任务已下载的文件，或打开文件所在文件夹（资源管理器中定位选中）。

## 打包为 EXE

双击 `打包EXE.bat`，成功后将整个 `dist\PersonalDownloader` 文件夹复制到其他 Windows 电脑，运行其中的 `PersonalDownloader.exe`，无需安装 Python。该便携目录包含 yt-dlp、FFmpeg、Tk 和系统托盘依赖。关闭主窗口会最小化到任务栏并显示系统托盘图标；任务栏按钮或托盘图标均可重新打开，托盘图标右键可彻底退出。更新版本时，先从托盘右键退出旧实例再启动新版。浏览器扩展仍需单独复制 `browser-extension` 文件夹并在目标电脑的 Chrome/Edge 中加载。

大文件默认最多 8 路 Range 并发下载到隐藏分段文件，全部完成后按顺序合并。任务和分段保存在 `%USERPROFILE%\\.personal-downloader`，关闭应用后可再次启动续传。YouTube / Bilibili 播放器请求到的 CDN 地址可能是临时分段或有防盗链的媒体地址；优先发送原视频页面，由 yt-dlp 解析完整格式。

## 浏览器媒体探测扩展（Chrome / Edge）

1. 打开浏览器扩展管理页并启用开发者模式。
2. 选择“加载已解压的扩展程序”，选中 `browser-extension` 文件夹。
3. 先启动下载器。视频页（YouTube、Bilibili 及 yt-dlp 支持的其他站点）点“发送当前视频页到下载器”；普通文件下载默认自动接管（扩展弹窗中可关闭“自动接管我点击的文件下载”），直接点击网页下载链接即可。浏览器触发的任务会先弹出“新建下载任务”确认框——可修改文件名、点“浏览…”切换保存路径，确认后才开始下载；取消则不创建任务。窗口被最小化时会自动唤到前台。

扩展在响应头到达时捕获媒体请求，并通过页面 Resource Timing 监视 MSE/fetch/XHR 资源。播放器列出的 CDN 地址可能过期或受 Referer / 登录态限制；下载时优先由 yt-dlp 从视频页面链接获取完整格式清单。Chrome 文件接管默认开启，但只转发最近 8 秒内真实点击链接或按钮后创建的下载（包括 fwlink 等跳转链接、按钮经 JS 触发的下载和常见重定向）；页面自行发起、没有任何点击的下载不会转交。本机下载器接收成功后取消 Chrome 下载并自动开始任务，应用未运行或无法接收时 Chrome 原下载继续。转交时扩展会一并带上浏览器的 User-Agent 和请求 Referer（优先 Chrome 实际使用的 Referer，缺失时用点击所在页面），避免校验请求头的服务器返回 403。若浏览器设置了“下载前询问保存位置”，需关闭后重新点击链接，扩展才可无弹窗自动接管。应用在 `127.0.0.1:18765` 开启仅本机的任务接收端，只接受浏览器扩展来源的地址，不接受下载命令或 Cookie。应用不解密或绕过加密、DRM 或访问控制。

站点解析不读取登录 Cookie，只下载公开可访问的视频。登录、地区、令牌或站点接口变化可能影响下载，见 [yt-dlp 提取器说明](https://github.com/yt-dlp/yt-dlp/wiki/Extractors)。

YouTube 与 Bilibili 视频页都发送页面 URL，由 yt-dlp 解析完整格式清单并自动用 FFmpeg 合并音视频（现代 YouTube 只提供分离的音视频流，合并流很少出现）。其他 yt-dlp 支持的站点（TikTok、Vimeo、X/Twitter 等数百个）同样发送页面 URL 即可；yt-dlp 不认识的页面会被拒绝并提示。部分站点（如抖音）需要浏览器登录态，yt-dlp 直接解析会失败——此时可在 Chrome 中登录并播放视频，用扩展媒体列表的“发送此流”经浏览器会话下载。解析 YouTube 时若系统装有 node 或 deno，会自动作为 yt-dlp 的 JS 运行时。若页面解析被登录或反机器人验证拦截，可播放视频后，在扩展媒体列表中检测到的单条媒体流上使用“发送此流”作为兜底。此功能只向本机下载器发送临时媒体 URL，以及浏览器 UA、页面 Referer/Origin 等非 Cookie 请求头；不读取或传输 Cookie。媒体 URL 有时效，需在播放时发送。若站点不允许该流或链接过期，下载仍会失败，可刷新页面重新播放后再发送。

## 参考项目

- [yt-dlp](https://github.com/yt-dlp/yt-dlp)：站点解析、格式选择、分段下载、FFmpeg 合并。本项目调用 Python API，不复制其提取器代码。
- [aria2](https://github.com/aria2/aria2)：普通直链并发 Range 与断点续传设计参考；本项目未复制其代码。

## 当前范围

- HTTP/HTTPS 直链任务、Range 分段、暂停和续传
- YouTube / Bilibili 等 yt-dlp 支持的视频页面解析、格式下载和音视频合并
- 下载列表右键打开文件或所在文件夹
- Chrome 文件下载接管（默认开启，可在扩展弹窗关闭）
- 浏览器媒体探测扩展和任务持久化

## 限制

- 站点解析不读取登录 Cookie，只下载公开可访问的视频；账户要求、短时令牌或站点策略可能阻止下载。
- 尚无 FTP、BT、队列优先级或速度限制。
- 网页探测看不到页面没有实际请求的媒体资源。
